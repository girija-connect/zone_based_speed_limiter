# Zone-Based Speed Limiter on ROS2 Navigation Stack

## Description

This project introduces a Zone Based Speed Controller for a mobile robot operating with the **ROS2 Navigation Stack (Nav2)**. 
The purpose of this node is to automatically reduce the robot’s velocity when it enters designated areas on the map that require safer movement.
The system listens to the velocity commands generated by the navigation system and monitors the robot’s position using localization data. 
If the robot moves into a predefined zone, the node restricts the forward velocity to a safe limit before sending the command to the robot.

The node subscribes to the following topics:

- `/cmd_vel` – velocity commands generated by the navigation stack
- `/amcl_pose` – estimated robot pose from AMCL localization

After processing these inputs, the node republishes the adjusted velocity command to:

- `/cmd_vel_safe`

Such speed control mechanisms are widely used in **autonomous mobile robots (AMRs)** deployed in environments like:

- warehouses
- hospitals
- factories
- human-shared spaces

These zones help ensure safer robot behavior in areas with higher risk or human presence.

----------------------------------------------------------------------------------------------

# Key Features

- Dynamic speed control inside predefined zones
- Uses **AMCL localization** to track robot position
- Intercepts and modifies navigation velocity commands
- Compatible with the **ROS2 Nav2 navigation framework**
- Verified using **TurtleBot3 simulation in Gazebo**

# Building the Package

### 1 Create a ROS2 workspace

```
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws/src
```

### 2 Add the package

Copy the `speed_zone_limiter` package into the `src` directory.

### 3 Compile the workspace

```
cd ~/ros2_ws
colcon build
```

### 4 Source the workspace

```
source install/setup.bash
```

# Running the Simulation

## Step 1 Start the TurtleBot3 simulation

```
export TURTLEBOT3_MODEL=burger
ros2 launch turtlebot3_gazebo turtlebot3_world.launch.py
```
Starts the Gazebo simulation environment with the TurtleBot3 robot loaded in the default world.

----------------------------------------------------------------------------------------------------

## Step 2 Start the Navigation Stack

Open another terminal and run:

```
export TURTLEBOT3_MODEL=burger
ros2 launch turtlebot3_navigation2 navigation2.launch.py use_sim_time:=True
```

Launches the Nav2 navigation stack, AMCL localization, and RViz while enabling simulated time from Gazebo.
---

## Step 3 Start the Speed Zone Controller

Run the following command in a new terminal:

```
ros2 launch speed_limiter speed_limiter.launch.py
```
Starts the speed zone limiter node, which monitors the robot position and limits velocity when it enters the defined zone.

# Testing Procedure

1. In **RViz**, select **2D Pose Estimate** to set the robot’s initial pose.

2. Use **Nav2 Goal** to send a navigation target.

3. When the robot moves into the defined slow zone, the controller automatically limits the robot’s speed.

4. Verify Using Terminal Commands

5. Add → By topic → /speed_zone_marker → Marker (Fixed Frame = map) to display the red speed zone outline.


You can monitor the output velocity using the following command:

```
ros2 topic echo /cmd_vel
```

Example behavior:

Robot outside zone → normal speed
Robot inside zone → velocity limited to 0.1 m/s

# Working Principle

The system operates using the following workflow:

1. The **Nav2 navigation stack** publishes velocity commands on `/cmd_vel`.

2. The **Speed Zone Controller** node subscribes to these commands.

3. The robot’s current position is obtained from the `/amcl_pose` topic.

4. The node checks whether the robot’s coordinates fall inside a predefined slow zone.

5. If the robot is within the zone, the forward velocity (`linear.x`) is reduced to a safe value.

6. The updated velocity command is then published to '/cmd_vel_safe'.

7. The robot executes motion based on the modified velocity command.
